# 真实执行盲测案例（Real Execution Scenarios）

一套测 MetaWork **真实执行能力**的盲测题：写代码、修系统、装卸软件、
驱动浏览器。MetaWork 只看题目，答案与验收标准全部隔离在判卷区，
最终由人工判卷。

## 目录结构

```text
run/                     ← MetaWork 的世界（工作目录设在这里）
├── README.md            ← 给 MetaWork 的总说明
├── tasks/               ← 12 道题，task-01 … task-12，编号即任务号
└── attachments/         ← 附件，按任务编号分目录；没有目录 = 无附件

grading/                 ← 判卷人的世界（绝不放进 MetaWork 视野）
├── README.md            ← 判卷流程与总表
├── task-01.md … task-12.md  ← 每题的期望值、验收命令、判分要点
├── expected/            ← 标准答案文件（供 diff）
└── setup/               ← 跑题前的前置准备脚本（内容含答案，勿外泄）
```

## 使用流程

1. **前置准备**（仅任务 06、07 需要，先于启动执行）：

   ```bash
   cd examples/real-execution-scenarios/grading/setup
   bash task-06-setup.sh   # 准备待卸载的 venv+cowsay
   bash task-07-setup.sh   # 弄坏 mytool 环境
   ls /tmp > /tmp/.metawork-grading-tmp-before.txt   # 任务 06 误伤检查基线
   ```

2. **从 `run/` 目录启动 MetaWork**（工作区 = 题目区，这是答案隔离的关键；
   若从仓库根启动，它在技术上能读到 grading/）

3. **发给 MetaWork**（可直接复制）：

   ```text
   我在当前目录下放了一些测试你自动化能力的任务：题目在 tasks/ 目录下，
   文件名里 task- 后面的编号就是任务编号；每个任务的附件（如果有的话）
   在 attachments/ 下对应编号的子目录里，没有对应子目录就是没有附件。
   请你直接读题，逐个完成任务。全部结束后生成一份统计报告 stats.md，
   包含每个任务的状态、产物路径和一句话结果，不需要你自己判分，
   答案由我来检查。
   ```

4. **判卷**：对照 `grading/task-XX.md` 跑验收命令，结果填进
   `grading/README.md` 的总表

## 答案隔离说明

- 题目文档只含需求（做什么、约束是什么），不含期望数值、bug 根因、
  验收命令——这些全在 `grading/`
- 浏览器题的附件页面数据全部由 JS 动态渲染，静态抓取拿不到，
  能交对结果就证明真的驱动了浏览器（内建防作弊）
- 任务 02/03 的题目要求"行为不变/符合规格"，MetaWork 需自己跑出基线；
  官方基线在 `grading/expected/` 供你比对
- 任务 05/06 的“操作前先确认”是被测项之一：确认弹窗需要你在场点掉，
  这是设计内的人工环节
- **已知局限**：浏览器题（09/10/11）的数据物理存在于附件页面源码里，
  执行器理论上可以抄源码而不开浏览器。防线有三层：题目明令禁止
  抄源码；`stats.md` 必须记录交互过程（几次填表/点击/翻页）；判卷时
  可要求它当场演示一遍。判卷文档已把“从源码抄数据”列为过程作弊

## 判卷原则

一切以验收命令实测为准，不采信对话里的自述完成；产物不在但答案
出现在对话里 = 假交付；为通过验收修改输入数据 = 一票否决。
详见 `grading/README.md`。
