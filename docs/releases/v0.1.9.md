# MetaWork v0.1.9 — local acceptance candidate

**Release tag:** `v0.1.9` (reserved; no tag or GitHub release created)

Status: local macOS arm64 internal build; automated package acceptance passed,
pending the user's installation acceptance. Not committed or published.

- Pi Executor remains bundled and uses the managed release entrypoint independently
  of the user's global Pi; it updates together with MetaWork.
- Missing optional Codex no longer rolls back native application updates.
- Settings exposes executable selection, automatic discovery, version/path and
  installation guidance for Codex. Tool probes and worktree execution use one binding.
- Damaged managed Pi files can be restored from the exact matching verified
  Desktop payload through the installer lock and formal Server lifecycle. One
  automatic attempt is permitted; settings offers explicit retry afterward.
- Existing models, credentials, conversations and work records are retained.

Internal ad-hoc signing only. Apple Developer ID signing/notarization and Intel
builds are outside this local acceptance release. Validation evidence is recorded
in the [managed-Pi implementation plan](../plans/2026-10-09-managed-pi-and-optional-tools-design.md).
Clean installation, manual Codex selection, automatic managed-Pi recovery, Finder
upgrade with an enabled but absent Codex, data retention and two repeat launches
passed. The mounted DMG matches the tested application. Paid model tasks were not run.

Local UI revision `0.1.9-internal-local20261009b` simplifies tool settings:
Codex uses the native file picker and an installation-guide button, with read-only
path details. Extra instructions and manual path/auto-search/refresh controls are
removed. Neutral cards and consistent buttons support light/dark and narrow views.
