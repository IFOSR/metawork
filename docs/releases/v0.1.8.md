# MetaWork v0.1.8

**Release tag:** `v0.1.8`

v0.1.8 fixes the macOS Desktop update lifecycle and recovery path. A failed
readiness check or interrupted shell replacement now releases the helper lock
before relaunch, keeps repair separate from applying an old request, and records
only safe stage/error codes for support. A newly downloaded Desktop can provision
its verified recovery helper even when the previous helper or staging directory
is missing.

The arm64 Desktop package now starts the updater and Desktop-managed Server
through one-shot macOS user-session jobs, uses a valid internal MetaWork app seal,
removes the confusing file-installation menu, and shows update progress with
repeat-click protection. First launch remains model-free; models are configured
later in Settings.

The release workflow validates both macOS architectures against the previous
latest DMG. It injects a failed candidate readiness check and a killed update
helper, then verifies rollback, repair, retry, authenticated rendering and
preservation of configuration, credentials and account facts.

If an older installation reports **修复未完成的更新**, launch this version and
choose **MetaWork → 修复未完成的更新…**. Keep the installation directory and
upgrade journal intact; do not delete databases or switch release pointers by
hand. See [Desktop release and recovery](../current/releasing.md).

This internal release contains the macOS arm64 DMG only. It is ad-hoc signed for
internal use and is not Apple Developer ID signed or notarized.
