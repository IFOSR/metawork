# MetaWork v0.1.24 (Internal)

**Release tag:** `v0.1.24`

Internal build. Not submitted to the App Store and not Apple-notarized.

## Fixes

- Desktop background updates no longer fail in a loop at the stop stage. The
  update stopped the previous Server with a fixed grace window and treated a
  non-zero stop CLI exit as a failure, so a drain that legitimately ran longer
  (an unreachable memory engine is enough) aborted the upgrade, rolled it back,
  and left the app on "准备完成更新 — 诊断编号：stop/unexpected" for every retry.
  The stop step now succeeds when the installation has no live instance left:
  the CLI result is informational, the drain is awaited, and a stuck exit is
  reclaimed.
- A Server that hangs before withdrawing its endpoints no longer blocks the
  upgrade forever. The explicit update/repair path may now force that exit, and
  only after the launchd job and process identity are re-verified; ordinary
  connect still never forces a Server that has not withdrawn its endpoints.
- A failed background update now records its reason in
  `upgrades/desktop-helper.log` (`Desktop update failed: …`) next to the
  stage/code that the UI shows, instead of discarding it.
- Includes everything from v0.1.23: bounded Server shutdown with an exit
  watchdog, the final memory deposition no longer being lost on every clean
  stop, `metawork server status` reporting a stuck instance, and
  `metawork server stop --force`, plus everything from v0.1.22.

## Downloads

- Apple Silicon Desktop: `MetaWork-darwin-arm64.dmg` (ad-hoc signed; on first launch
  allow it in Finder or run `xattr -dr com.apple.quarantine /Applications/MetaWork.app`).
- Server installers for `darwin-arm64`, `darwin-x64` and `linux-x64` plus their
  signed manifests.
- macOS Intel Desktop is not packaged for this internal build; use the Server
  installer on Intel Macs.
