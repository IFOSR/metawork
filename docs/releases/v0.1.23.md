# MetaWork v0.1.23 (Internal)

**Release tag:** `v0.1.23`

Internal build. Not submitted to the App Store and not Apple-notarized.

## Fixes

- Stopping the local Server can no longer leave a zombie process behind. Node
  cannot bound its own exit: `process.exit()` waits on the threadpool join with
  no timeout, and a process stuck there keeps no listener, no lock and no
  endpoint while still holding the account database. The Server now arms a
  detached exit watchdog (`METAWORK_EXIT_WATCHDOG_MS`, default 60s) before it
  drains, so a stuck exit is reclaimed by `SIGKILL` after the budget instead of
  surviving until the machine reboots.
- The final long-term-memory deposition is no longer lost on every clean stop.
  Shutdown released AccountRuntime storage before the memory drain, so the
  deposition always failed with "The database connection is not open". The
  deposition now runs before storage is released, every shutdown step is
  attempted even if an earlier one fails, and storage is always released.
- `metawork server status` distinguishes a live process from a dead one again.
  The instance lock is no longer deleted before the process exits; a lock past
  the startup window with withdrawn endpoints is reported as a stuck instance
  instead of "not running".
- `metawork server stop --force` / `metawork server restart --force` reclaim that
  instance: SIGTERM, then SIGKILL after the grace window, and when the lock is
  already gone, a scan restricted to this user and to
  `…/app/releases/<release>/dist/index.js server start` under this install root.
- Desktop recovers from the same state without a manual `kill`: the stop action
  no longer requires a reachable endpoint, `connect` reclaims an instance that
  withdrew its endpoints before bootstrapping a replacement, and forced cleanup
  no longer refuses a withdrawn Server merely because it still holds database
  descriptors (it cannot admit work and SQLite is crash-safe in WAL mode).
- Stop reasons are auditable. The Server records
  `MetaWork shutdown requested: signal=… ppid=… uid=… argv=…`, and the Desktop
  appends `reason=user-stop|update|pi-repair` to `logs/desktop-restart.log`, so an
  unexplained stop is traceable to a caller instead of taking hours of forensics.
- Includes everything from v0.1.22: bundled memory engine in Desktop installs and
  upgrades, the upgrade deadlock fix, runtime-owned `configurationRevision` with
  repeated-rejection reporting, and everything from v0.1.21.

## Downloads

- Apple Silicon Desktop: `MetaWork-darwin-arm64.dmg` (ad-hoc signed; on first launch
  allow it in Finder or run `xattr -dr com.apple.quarantine /Applications/MetaWork.app`).
- Server installers for `darwin-arm64`, `darwin-x64` and `linux-x64` plus their
  signed manifests.
- macOS Intel Desktop is not packaged for this internal build; use the Server
  installer on Intel Macs.
