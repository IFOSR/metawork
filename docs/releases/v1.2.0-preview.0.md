# AnyFusion v1.2.0 Preview

**Release date:** 2026-07-17

**Release tag:** `v1.2.0-preview.0`

**Status:** Developer Preview · Limited Internal Pilot

AnyFusion is a strategic open-source initiative backed by AnyInt and MetaFusion, with core development led by AnyInt. The project is hosted by MetaAny as a neutral open-source home.

## Highlights

- Durable task lifecycle with resumable execution and persistent state.
- Planning and authorization separated through `PlanningAgent` and `PolicyKernel`.
- Persisted dependency-aware work graphs with explicit acceptance criteria and executor candidates.
- Isolated executor work units with scoped context and dependency handoffs.
- Evidence-aware verification, artifact extraction, and terminal or Gateway delivery.
- Local-first operation with Codex as the default planner and executor, plus additional executor adapters.

## Architecture

AnyFusion separates the agent workflow into explicit runtime boundaries:

1. TUI, CLI, Gateway, or Feishu accepts a user request.
2. The session layer constructs bounded planning context.
3. `PlanningAgent` proposes conversation, task-control, or work-graph semantics.
4. `PolicyKernel` validates, rewrites, rejects, or requests clarification before state changes.
5. Durable tasks and subtasks are persisted and scheduled by dependency readiness.
6. Executor work units receive scoped assignments rather than raw user input.
7. Verification and delivery services record evidence, artifacts, and final results.

See the repository Technical Overview and current Architecture Decision Records for the complete contract.

## Current Deployment Status

**Status:** Deployed for limited internal pilot use.

**Current scope:** One active top-level task with dependency-aware subtask execution.

The public CI gate validates deterministic repository behavior through TypeScript checks, the Vitest suite, and production builds. Credential-dependent live-model smoke tests remain an internal validation gate.

## Known Limitations

- Only one top-level task can be active at a time.
- Public CI does not execute real model calls or external delivery integrations.
- CLI, configuration, and runtime contracts may change before a stable release.
- Some task-command and TUI workflows remain under active development.
