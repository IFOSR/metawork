# MetaWork v0.1.27 (Internal)

**Release tag:** `v0.1.27`

Internal build. The Apple Silicon Desktop is ad-hoc signed and is not Apple-notarized.

## Architecture

- The kernel control axis is retired in favour of the `src/control` contracts and
  the Planner-owned proposal/validation boundary (ADR-0055). The vendored
  `planner/AnyFusion-Pi` fork and the Docker runtime assets are gone; the
  packaged Manager and Executor run the pinned upstream Pi (1.5.0).
- Planning facts now carry the Workspace root plus the execution write fact
  (Executor commits in the Conversation Git worktree, Runtime merges the result
  back). The Manager's own read-only tool surface is an extension constraint, not
  a property of the Workspace, so "implement this" no longer returns a
  clarification asking which directory may be written.
- Clarifications are reserved for user-intent ambiguity. Runtime owns the "cannot
  write" case and reports an actionable Git/admission reason instead.

## Execution and recovery

- A blocked Subtask whose failure is recoverable (configuration, adapter,
  permission, stale receipt) keeps the Task `needs_action` instead of finalising
  it, so "继续未完成部分" can resume. Server start refuses an incomplete runtime
  build and names the rebuild step instead of surfacing an unactionable `ENOENT`.
- Reconciliation parks a Task that was left `executing` with a blocked Subtask and
  no live dispatch, cancelling the idle replan and concluding the block through the
  Task state authority. Completed Subtasks keep their receipts.
- Reconciliation also cancels orphan replan requests of terminal Tasks, so a failed
  Task can no longer leave the Conversation slot `releasing` and queue every later
  Task forever.
- `recoverDue` dispatches when runnable work exists, so a Task unblocked by an
  accepted result actually resumes. An explicitly accepted receipt counts as a
  completion source, so acceptance no longer ends in
  `workspace_completion_missing_certified_results`.
- Running or terminating a process requires exclusive Workspace access even
  without file changes, and external process termination is gated on an explicit
  user turn.
- Schema 67 upgrades to 68 in place: `task_operation_results.outcome` gains
  `repair_pending`, the table is rebuilt with its rows preserved, and older or
  malformed schemas are still refused.
- Anti-bot/verification pages detected by `web_fetch`/`web_search` return a
  blocked, retryable source instead of the verification text.
- Router unavailability falls back to the deterministic default binding
  (`selection: default_fallback`) instead of blocking every Subtask. Only a
  genuinely empty candidate set blocks. The retired `originalFilePolicy` admission
  gate is removed; Conversation Git Worktree execution and the merge queue own
  that answer.

## Web

- The Manager planning process is observable: the live planning card shows the
  phase timeline, tool names, argument/result field names and elapsed time, and
  expands in place instead of opening a full-height dark drawer. It disappears
  with the card once the turn is sealed, so a Q&A turn no longer pins
  "规划中 0s".
- Trace events no longer carry a status, so finished turns stop showing endless
  `running` progress events and their pulse animation.

## Desktop

- A Desktop launch that finds an interrupted update whose restore stage failed now
  isolates the incompatible installation (never a symlink, never while a previous
  update helper or background server is alive), installs the current version
  cleanly, and restores the previous installation if that clean install fails
  before it becomes usable. If the old background process is still exiting, the
  app reports it without touching installation files and retries on the next open.
- Choosing a data directory accepts an empty directory to start a new installation,
  and rejects a non-empty directory that is not an existing MetaWork installation.
- `electron-builder` packages the pinned local Electron distribution, so builds do
  not depend on a second checksum metadata fetch.

## Packaging

- Runtime, Planner, Memory and Pi archives are built from an explicit runtime
  allowlist: development toolchains (`typescript`, `vitest`, `esbuild`, `tsup`,
  `vite`, `rollup`, `@types`, `.bin`, editor config and repository `docker`/
  `.github` trees) are excluded from the published tarballs. The Apple Silicon
  DMG shrinks from roughly 465 MB to roughly 345 MB for the same product surface.

## Validation

- `npm run lint` (tsc --noEmit), `npm run lint:desktop` and
  `npm run test:desktop` (12 files / 32 tests) pass.
- A clean installation from the packaged Desktop reached its ready state against
  its bundled runtime, served the Web UI with HTTP 200, reported an authenticated
  local session, and ran the installed Executor Pi with the expected
  `--provider`/`--model` contract.
- The Desktop background-update gate applied this payload through the real
  `SourceNativeUpdater.update()` over the previously installed release: the
  upgrade committed, `app/current` became `0.1.27-build-7f348ba`, the upgrade id
  stayed inside the configuration-reference grammar, and the bundled memory engine
  is present.
- `apps/desktop/tests/packaged-install-smoke.mjs` does not finish on this build:
  it asserts that saving the empty configuration through "保存并激活" issues
  `POST /api/config/activate`, but the current Settings panel disables that button
  until every required role has a model bound. The clean install, readiness,
  authenticated-session and installed-Pi assertions before that step pass. The
  stale assertion is not fixed here.
- The full `npm test` suite is not reported green for this internal build; the
  failures documented for v0.1.26 remain in the same areas and are not claimed
  as resolved here.
