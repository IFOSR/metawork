# MetaWork v0.1.25 (Internal)

**Release tag:** `v0.1.25`

Internal build. The Apple Silicon Desktop is ad-hoc signed and is not Apple-notarized.

## Fixes

- Fix the recovery loop where Continue had no recoverable step and a subsequent
  result retry was rejected as expired. Exhausted completion correction now waits
  for explicit acceptance or retry; old implicit accepts cannot consume the retry.
- Replace stale result controls with the current result identity. Completed,
  failed and cancelled Tasks no longer expose old acceptance/retry buttons.
- Finish a control-command interaction when its reply is ready, independently
  of other background work. Stop targets the work associated with that interaction.
- Correct historical running indicators through both initial and incremental
  WebSocket updates. Reconnects and equal-revision terminal corrections converge
  automatically; users do not need to refresh the Desktop or delete history.
- Remove optional OpenAI output-token caps from Pi Executor requests, including
  response-only corrections. Provider limits still apply; Anthropic's required
  `max_tokens` remains present.
- Use the current shared Gateway protocol version for Desktop readiness checks.

Previously accepted terminal results remain historical facts. This update does
not regenerate those answers or restore conversations the user has deleted.

## Validation

- 302 focused tests across 21 files covering Kernel, durable recovery, result
  identity, cancellation, observation, client state and Desktop readiness.
- A real Chrome + built Server/Web regression covers Stop disappearing after
  command completion and staying settled after reconnecting the interface.
- Type checks, native builds and isolated Desktop upgrade checks.

Full CI is not green: release-source run `41951402784` reports 56 failed tests.
53 match tests already failing in baseline run `41831024264`; the other three
were outdated command-state, recovery-fixture and wording expectations. Those
expectations are corrected in a test-only main-branch follow-up, with all 58
tests in the four affected/adjacent files passing. No packaged application code
changes in that follow-up. The remaining full-suite failures are not claimed
as resolved by this internal release.
