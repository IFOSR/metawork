# MetaWork v0.1.4 Release

**Release tag:** `v0.1.4`

**Release date:** 2026-10-05

**Channel:** `stable`

This release improves model and Agent settings, model selection, and task
presentation, and fixes the Unix installer's GitHub manifest download path.

## Highlights

- Collapsible model services and Agents make larger configurations easier to
  browse. Existing models can be edited; Planner has its own model selection.
- Model information comes from OpenRouter's public catalog, with explicit
  matching when local names differ. Prices are converted to CNY at USD × 7
  and remain editable. Detailed evidence and public parameter cards are kept.
- Model selection uses duties, detailed strengths, limitations, suitable tasks,
  available tools, and prices. Generic coding/planning labels no longer score
  candidates; concrete execution compatibility checks remain enforced.
- Settings AI rewriting, Agent capability explanations, and model summaries use
  an independent internal LLM. Progress, changed/unchanged results, and failures
  are visible; late responses cannot overwrite newer edits.
- Saving and activating configuration no longer calls Planner or waits for
  another OpenRouter request. Provider credentials remain separate even when
  Providers share an endpoint.
- Conversation observation and task switching fixes preserve visible history;
  the trajectory includes the inline Work Graph DAG and clearer progress.

## Installation and update

macOS, Linux, and WSL2:

```bash
curl -fsSL https://raw.githubusercontent.com/IFOSR/metawork/main/scripts/install.sh | bash
```

Windows x64:

```powershell
irm https://raw.githubusercontent.com/IFOSR/metawork/main/scripts/install.ps1 -OutFile metawork-install.ps1
.\metawork-install.ps1
```

Both installers follow GitHub Releases' latest stable version. Stop a running
Server before updating, then restart it afterward. Existing configuration,
credentials, and task data are preserved by the native update transaction.

## Native artifacts and verification

macOS Intel (`darwin-x64`), macOS Apple Silicon (`darwin-arm64`), Linux x64
(`linux-x64`), and Windows x64 (`win32-x64`) are built on native runners from
the same tagged commit. Each target supplies Runtime and vendored AnyFusion-Pi
Planner archives plus an Ed25519-signed manifest. Publication verifies the
complete set's identity, signatures, sizes, and SHA-256 hashes before promotion.
Linux arm64 remains a source/native build target without a prebuilt artifact.

## Internal AI configuration

Developers provision the installation's independent `internal/llm.json` and
`internal/llm-credentials.json` as described in the
[internal LLM guide](../current/internal-llm-service.md). Private API keys are
not distributed in release archives. Existing installations retain these files.
An installation without this service reports AI actions as unavailable; manual
settings editing and activation remain usable and do not fall back to Planner.
