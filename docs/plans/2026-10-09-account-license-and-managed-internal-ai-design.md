# MetaWork 一期账号授权与官方内置 AI 最终方案

- 方案日期：2026-10-09
- 状态：实施中；验收证据与剩余事项见文末，不代表全部完成。
- 确认依据：用户确认每个本机 Server 同时仅登录一个官方账号，切换必须先退出；活动任务期间的后台定期授权查询改为每天一次，其余上一轮方案保持不变。
- 文档定稿日期：2026-10-09
- 实施完成日期：2026-10-09（本地 Server seam、官方参考服务和 huoshan 部署已完成；真实支付与上游模型密钥仍按方案保持未接入）。
- 交付验证：`npm run lint`、Web 构建、授权服务单元测试通过；huoshan systemd 服务、HTTPS 健康检查、账号创建、试用激活、登录、权益查询和待支付订单链路通过。
- 收尾提交：未创建提交，等待用户验证。

## 1. 核心决策

MetaWork 采用官方账号授权。用户通过 Web 或 Desktop 登录，登录状态归属于客户机器上的 MetaWork Server；Web、Desktop、TUI、飞书共享该 Server 的授权状态。

1. License 绑定官方账号，不绑定机器硬件、MAC 地址或硬件指纹。
2. 每个本机 Server 同时仅登录一个官方账号；换账号必须先退出，不静默切换或合并本地数据。
3. 不做账号共享治理、设备数量限制和多机并发登录限制。
4. 不做短租约、离线 License、Access Token + Refresh Token 自动刷新体系。
5. 保留普通官方登录会话，以识别已认证的本机 Server；会话标识仅由本机 Server 在内存中持有。
6. Server 停止、崩溃、升级重启或电脑重启后，需要重新登录，不自动恢复官方会话。
7. 内置 AI 的 Provider、Model ID、API Key、模型地址和提示词模板只由官方服务维护。
8. 普通安装不再要求用户创建或维护 `internal/llm.json`、`internal/llm-credentials.json`。
9. 有活动任务时的后台定期授权查询为每天一次，不是每分钟一次。
10. 登录、新的生产性操作准入和官方内置 AI 请求仍分别执行在线核验；每日查询不取代这些事件触发的核验。

## 2. 系统边界

```text
Web / Desktop（登录与套餐入口）     TUI / 飞书（不提供官方登录入口）
              \                    /
               本机 MetaWork Server
               ├── 当前官方账号会话
               ├── 订阅状态与统一准入
               └── 既有 AccountRuntime / Kernel / Executor
                         │ HTTPS
                         ▼
                 MetaWork 官方服务
                 ├── 身份、会话与 License
                 ├── 套餐、订单与支付接口
                 └── 固定业务功能的内置 AI
                         │
                         ▼
                    实际模型供应商
```

一期官方服务采用一个后端服务和一个数据库，内部按职责划分，不拆复杂微服务。

本机 Server 也位于用户控制的环境，不能保管官方模型密钥或官方签名私钥。客户端只需要产品内置的官方 HTTPS 服务地址及协议支持；没有面向用户的内置模型配置文件。软件更新继续使用既有发布验签机制，与登录会话无关。

官方账号是商业身份，不直接替换既有本地 AccountRuntime、`local-default` 或本地访问控制。登录同一官方账号只共享订阅权益，不自动同步或合并不同机器上的 Workspace、Conversation、Task、文件和历史。

## 3. 安装与首次使用

安装向导最后一步提供登录和套餐选择；无交互安装方式在首次 Web / Desktop 启动向导中完成。安装本身无需模型凭证，可以完成文件安装、启动基础 Server 和展示登录页；有效订阅前不开放新的生产性服务。

流程：

```text
安装 / 首次打开 -> 登录官方账号 -> 查询已有权益
  ├── 已有有效权益：直接使用，不重复要求购买
  └── 无有效权益：选择试用、月度或年度 -> 激活 / 待支付
```

TUI 和飞书发现本机 Server 未登录时，提示先在本机 Web 或 Desktop 登录；订阅无效时提示激活或续费，不提供另一套账号登录和套餐逻辑。

## 4. 登录会话与生命周期

### 4.1 普通登录会话

用户通过 Web / Desktop 完成账号认证，官方服务登记一条本机 Server 登录会话，返回不可预测的随机会话标识。本机 Server 后续通过 HTTPS 携带该标识访问官方服务。

会话标识是敏感凭证，但不是模型 API Key、短期租约或用户维护的配置：

- 本机只在 Server 内存保存，不写数据库、配置文件、启动参数、日志、诊断报告或崩溃采集。
- 不下发给 Web Renderer、TUI、飞书等业务客户端；这些客户端使用现有本地连接身份访问 Server。
- 官方服务保存可撤销的会话记录；建议保存会话标识的安全摘要而非明文。
- 本地不保存用户密码；官方认证使用成熟安全实现，不自创密码存储协议。
- 官方服务可以撤销会话；本地收到明确失效响应后清除登录状态并提示重新登录。
- 不设置客户端定时刷新两套凭证的流程。

官方可记录账号、会话创建时间、最近活动时间、退出/撤销状态及基本客户端展示信息。可用随机 Server 运行实例标识辅助排障，但不将它作为硬件身份或认证依据。

### 4.2 生命周期

| 事件 | 结果 |
| --- | --- |
| Web 登录成功 | 同一本机 Server 的所有授权接入端共享登录状态 |
| Desktop 登录成功 | 同上 |
| 关闭 Web 标签页、Desktop 窗口或退出 Desktop | 不停止 Server，也不退出官方账号 |
| TUI 退出 | 不影响 Server 登录 |
| 主动退出账号 | 先关闭本地生产性准入、清除会话并推进安全收尾；向官方撤销会话 |
| Server 正常停止 | 尽力撤销官方会话，清除内存 |
| Server 崩溃、断电、重启或升级重启 | 不恢复官方会话，下次需重新登录 |
| 网络短暂中断 | 不直接清除登录；需要核验的生产性操作暂停 |
| 官方明确返回会话失效 | 清除登录并要求重新登录 |

退出请求不能因网络失败而继续保留本地使用权限。异常断电时不能保证官方实时收到退出；官方清理长期不活动会话属于记录生命周期管理，不是本地授权短租约。

并发登录、退出和核验响应须使用会话代次隔离：旧账号的迟到响应不得重新打开新会话的准入或覆盖状态。

### 4.3 单账号和本地数据

一期每个 Server 只有一个当前官方账号。第二次登录不同账号必须先退出；旧账号活动任务完成受控收尾前，不把执行或官方请求归属静默转交新账号。

退出不删除、迁移或合并本地数据。本地数据仍受既有本地访问权限管理；一期不提供按官方账号隔离同一安装数据的多租户能力。切换账号页面应说明这一点，避免误以为退出官方账号等于清除或隔离本地历史。

## 5. 套餐、试用与支付

| 类型 | 价格 | 有效期 | 开通方式 |
| --- | --- | --- | --- |
| 试用 | 免费 | 7 天 | 登录后主动选择，由官方首次激活 |
| 月度 | 人民币 ¥9.90 | 一个自然月 | 官方确认支付成功 |
| 年度 | 人民币 ¥99.00 | 一个自然年 | 官方确认支付成功 |
| 内部永久授权 | 内部使用 | 无到期时间，可撤销 | 仅官方后台授予 |

规则：

- 试用从官方成功激活时刻起算，同一官方账号不能通过重装、换机、删除文件重新获得试用。
- 不采集硬件指纹；批量新账号重复试用的治理不在一期范围内。
- 月度/年度为手动续费，不默认自动扣款。有效期内续费从现有到期时间顺延；已过期从支付确认时间起算。
- 官方以统一日历规则和时间基准计算自然月/年，处理月末及闰年，客户端展示明确到期时间，不自行计算权益。
- 支付尚未接入时，允许选择套餐和创建待支付订单，明确显示支付未开放，不能模拟支付成功或自动开正式权益。
- 用户可以明确改选试用，不静默替换套餐。
- 支付接入后由官方核验渠道交易、订单、金额、币种和支付状态，幂等处理回调；浏览器成功跳转不是授权依据。
- 内部永久授权不出现在公开套餐选择中，没有客户端管理员开关、万能激活码或免登录分支；永久权益不等于官方后台管理权限。
- 订阅覆盖软件使用权与合理额度的内置 AI，不默认包含用户 Planner / Executor 的模型消耗。现有 Query 用量事实与订阅订单分开。

## 6. 授权核验：每天一次后台查询，保留事件核验

### 6.1 登录与订阅是两种状态

登录回答“当前是谁”，订阅回答“当前是否有服务使用权”。持续保持登录不能延长试用或订阅。

本地至少区分：未登录、已登录且权益有效、未选择/待支付、权益过期/撤销、授权暂时无法确认。各客户端仅消费统一投影，不自行判断套餐或维护独立授权状态。

### 6.2 核验时机

| 触发 | 规则 |
| --- | --- |
| 登录成功 | 立即查询官方订阅事实 |
| 新的生产性操作准入 | 在请求进入生产性工作链前在线核验；同时请求可合并 |
| 有活动任务的后台定期查询 | 距上次成功核验达到 24 小时才发起每日检查，不按零点重复查询 |
| 无活动任务 | 不为该目的持续轮询；下一次生产性操作再核验 |
| 官方内置 AI 请求 | 官方每次独立检查当前会话和权益，无需本地预先重复请求一次 |
| 支付成功、主动刷新订阅 | 立即查询，不等待下一天 |
| 收到明确失效/撤销响应 | 立即更新准入状态，不等待每日检查 |

任何成功的在线权益核验都更新每日查询基准；多个客户端共享一个查询，不按端重复启动计时器。每日后台查询以 Server 为单位单飞执行；失败不进入高频后台重试，用户主动重试或后续操作可以触发新的核验。

“新的生产性操作”指用户或集成发起的新任务、Planner 语义请求、显式恢复/重试等工作入口，不是每个事件、每次状态投影或每个既有执行链内部步骤。已有工作内部的派发仍检查当前统一准入事实，不额外在每一步发网络请求。

### 6.3 已知到期时间不推迟到第二天

官方查询返回当前状态、生效时间、到期时间和服务端时间。本机在已知到期时刻停止新增工作，不因每日后台检查而多提供一天服务。

本机可结合服务端时间基准和单调经过时间避免普通系统时钟回拨延长有效期；休眠唤醒后若计时状态不可信，先重新核验。Server 重启不恢复缓存，必须重新登录。这不是签名租约，也不承诺抵御被修改的本地程序。

未经过其他事件核验的纯本地活动，对官方提前撤销或退款状态的发现可能延迟约 24 小时；本方案接受这个简化取舍。官方内置 AI 每次检查，因此不受该后台周期影响。

### 6.4 核验失败

需要核验而网络不可用或响应无法验证时，不把失败当作成功，也不继续无限使用旧状态：暂停新的生产性准入，活动工作进入受控安全收尾；保留历史、导出、取消和续费入口。网络失败不等同于账号已退出，连接恢复后可用原会话重试；明确会话失效才要求登录。

一天一次仅指周期性查询，不是新增一天离线授权保证。

## 7. 内置 AI 官方化

本地保留业务入口，底层调用固定官方业务接口，例如：

- Agent 职责改写；
- 模型资料摘要；
- Agent 能力和边界说明。

请求只包含业务操作、必要输入和请求标识；本机 Server 另附登录会话。客户端不传 Provider、Model ID、模型 API Key、模型地址或任意系统提示词。

官方负责会话与权益检查、固定提示词、模型选择、调用和业务 JSON 解析。响应只返回业务结果和安全错误，不透传原始 Provider response。本地设置消费者负责所需业务字段校验；AI 文本不得生成权限授予或绕过既有配置激活路径。

无论哪个模型被使用，用户界面只显示“MetaWork 内置 AI”。这不是保证用户无法从输出猜测模型；真正安全边界是上游 Key 永不下发。

2026-10-10 根据用户确认简化：仍只提供固定设置业务操作，取消 AI 专用大小/字数/输出 token 上限、强制推理模式、服务端重复 schema 和内容过滤、业务超时、频率/并发/日额度及请求去重。生成参数使用供应商默认值；保留基础 HTTP/JSON 通信和账号/权益检查，订单及登录校验维持原义。调用元数据仅用于审计，不作为额度门槛。

仅上传当前操作所需文本与必要上下文，不默认上传整个 Workspace、历史或凭证；在隐私说明中告知官方服务及模型处理用途，明确日志与保留策略。

## 8. 到期、退出与安全收尾

失去有效授权时：

- 阻止新任务、新 Planner 语义请求、新内置 AI 请求、新 Executor 派发和自动重试。
- 不直接强杀 Server 或破坏工作区；已启动尝试按现有可取消与清理边界受控收尾，不允许无限派生新工作。
- 允许取消、必要状态恢复、结果落盘、资源释放、清理、历史浏览、数据导出、登录、续费和更新。
- 未登录的启动恢复仅负责安全一致性和清理，不自动恢复生产性派发。
- 重新登录或续费后通过既有恢复流程继续，不伪造完成状态或直接改 Task 生命周期。

TUI、飞书未登录时提示到 Web / Desktop 登录，不另建授权路径。现有本地 Web 会话保护、Unix 连接权限和飞书消息来源验证继续有效；官方商业授权不等于授予任意客户端访问本地数据的权限。

## 9. 数据和模块职责

### 9.1 官方最小数据

- 官方账号：认证身份、状态。
- 登录会话：账号、随机会话摘要、运行实例辅助信息、创建/最近活动/撤销时间。
- License：账号、套餐、状态、生效/到期时间、权益修订号。
- 订单及交易记录：套餐、服务端价格、金额、币种、渠道确认、幂等标识。
- 内置 AI 基础用量与安全审计：必要元数据，不记录会话明文或无必要的输入正文。

本地仅保存既有工作数据；当前官方会话和授权缓存为内存状态。当前方案不要求新增本地持久化 License 文件。

### 9.2 唯一职责 owner

| 模块 | 拥有 | 不拥有 |
| --- | --- | --- |
| 官方身份/订阅模块 | 账号认证、会话、订阅真实事实 | 本地任务调度 |
| 官方订单模块 | 价格、订单、支付确认与权益依据 | 前端自报支付成功 |
| 官方内置 AI 模块 | 固定功能、模型配置、密钥与调用 | 本地配置激活和权限授予 |
| 本地授权应用服务 | 当前账号会话、在线核验、每日检查、规范化状态 | Task 状态修改、直接杀 Executor |
| Gateway / Application Shell | 登录入口、统一准入、状态投影、规范化事件 | 自行调度/恢复 |
| Kernel | 根据显式授权事实决定新增派发与安全停止政策 | HTTP、会话存储、直接读取系统时间 |
| Runtime | 执行 Kernel 决策、清理与事实回报 | 另一套授权/恢复政策 |
| Web/Desktop/TUI/飞书 | 展示并调用既有应用接口 | 各自维护 License 权威 |

拟新增的公开 seam：本地 `login/logout/getStatus/verifyEntitlement` 应用端口、官方会话与权益 HTTP 契约、内置 AI 固定业务端口、Kernel 可消费的规范化授权事实。精确类型与事件版本在实施 ADR 中冻结。

依赖遵循 ADR-0020：外围负责网络和会话，Kernel 只消费显式事实；UI 不直接访问存储，不引入第二调度器或 Planner 存储写入。

## 10. 迁移与实施前架构门

本方案不改变当前代码或把未交付目标写成现行事实。实施前新增 ADR，明确修订影响：

- ADR-0020：授权应用服务、Kernel 事实与适配边界；
- ADR-0031/0034/0039/0045：本地 Server 登录生命周期、Web/Desktop 入口、原有本地认证的关系；
- ADR-0044：本地 InternalLlmService 转向官方业务接口；
- ADR-0042：订阅与现有 Query 用量计费的分离；
- ADR-0023 及运行恢复契约：重启未登录时的安全恢复与生产性派发阻断。

届时同步更新 `CONTEXT.md`、当前技术总览和相关模块文档；本次只登记已确认方案，不预先覆盖现行技术说明。

迁移要求：

1. Linux、macOS、Desktop 及其他正式安装路径统一初始化登录引导，不复制研发模型凭证。
2. 既有本地内置模型配置不再是普通生产调用路径；不得自动上传旧 Key 到官方。
3. 明确停用/清理旧 internal 凭证的升级策略，不能误删用户 Planner/Executor Provider 凭证。
4. 如保留研发直连，仅限显式研发入口，不作为生产授权失败的回退；一期不建设企业私有 Gateway 产品模式。
5. 原 SettingsAssistant、画像摘要、能力说明消费者统一切换业务端口，删除普通生产对本地 internal 文件的依赖，避免两个并行权威。
6. 升级不静默授予永久权益，明确告知需要官方登录；历史数据保留且可导出。
7. 原本模型免费启动的安装仍能进入登录/设置基础页面，内置 AI 不可用不导致整个 Server 崩溃。

## 11. 一期交付步骤

1. **契约与 ADR**：冻结账号/会话/权益/错误投影、每日检查语义、执行准入和退出收尾规则。
2. **官方服务**：账户登录、普通会话、试用与后台永久权益、套餐和待支付订单、内置 AI 功能接口。
3. **本地 Server**：内存会话、单账号约束、退出、在线核验、每日后台查询和统一授权投影。
4. **多端入口**：Web/Desktop 登录与套餐页；TUI/飞书消费状态并引导，不新增登录机制。
5. **运行集成**：Kernel 授权事实、启动安全恢复、到期/退出收尾、内置 AI 消费者切换。
6. **安装升级与验收**：干净 Linux/macOS、新旧安装、多端、异常网络和真实官方服务联调。

所有阶段立即遵循职责边界；不以实施临时性为由新增第二授权权威或 Runtime 自主调度。支付真实接入可以后续完成，但待支付订单不得提供付费权益。

## 12. 验收标准

- 干净机器无需 internal JSON、模型 Key 或 Model ID，安装可进入登录与套餐向导。
- Web 登录后同 Server 的 Desktop/TUI/飞书共享状态；关闭客户端不退出 Server。
- 第二官方账号不能静默覆盖第一账号；退出后旧响应不能恢复授权，数据不自动合并。
- Server 重启、崩溃重启、升级重启必须重新登录，未登录不自动派发任务。
- 无硬件采集和机器绑定，同账号换机器登录可使用；无云端工作数据同步假象。
- 每日查询使用可控时钟验证：活动任务期间距上次成功核验 24 小时检查，非每分钟、非每端检查；空闲不持续轮询。
- 登录、新生产性入口、官方 AI 的事件核验独立有效；检查失败不高频重试或无限放行。
- 已知到期时刻及时关闭新增准入；撤销最迟被下一次核验发现；睡眠唤醒及系统时间变化不意外延长缓存。
- 无网络可查看/导出/取消和安全收尾，不新开生产性工作；网络恢复与会话失效区分。
- 试用重装不重置；套餐由服务端定价；待支付无权益；重复支付回调不重复加时长。
- 内部永久权益仅后台签发，无公开管理员选项或绕过开关。
- 发布包、日志、页面、诊断和客户端接口无模型 Key、真实模型配置及官方会话标识。
- 内置 AI 输出仍受业务校验，设置保存/激活仍确定性执行，不隐式依赖 AI。
- 验证退出、到期、断网期间的派发、重试、清理和恢复，证明未绕过 Kernel 唯一决策权。
- 持久化如有变更，仓储测试与 Docker 测试同步；跨平台验收记录真实证据，不以单元测试替代部署验收。

## 13. 安全能力与明确非目标

能保证的设计目标：模型 Key 不下发；客户端不能修改官方数据库中的 License；官方每次请求独立核验；不使用本地到期文件作为官方授权依据。

不能承诺：用户完全不能修改本地程序、跳过本地检查、读取进程内会话，或从模型输出推测供应商。每天核验的简化也不提供纯本地活动的即时远程撤销。

一期不做：硬件绑定、账号共享治理、设备数量限制、短租约、长期离线许可、双令牌刷新体系、TUI/飞书独立官方登录、跨机器工作数据同步、官方账号级本地多租户隔离、通用大模型代理和复杂微服务拆分。
