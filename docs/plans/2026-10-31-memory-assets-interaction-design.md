## 1. 用户目标与设计取舍

用户来这里应能回答四个问题：系统记住了什么、这条记忆是否准确、是否允许以后使用、如何纠正或移除。

页面名称使用「记忆」，列表名称使用「已保存的记忆」。不要求用户理解 persona、episodic、instruction、Provider、FTS 等术语。记忆属于当前账号，跨 Workspace 使用；「可使用」表示允许参与相关任务的召回，不表示每次任务必定引用。

采用安静、清晰、紧凑的工作工具风格。白色或现有深色主题背景，分隔线列表，小面积强调色，避免一条记录一个巨大灰色卡片。沿用现有字体与主题 tokens，不引入新设计系统或依赖。

首版不添加仪表盘、记忆评分、批量操作、自动分类规则编辑器。主操作是打开一条记忆、理解它、管理它。

## 2. 闪烁诊断与确定性修复

代码证据：

1. `web/src/components/SettingsPanel.tsx` 的 effect 每 1,000ms 调用 `getActivationStatus` 并 `setActivationState`。
2. 同一组件在 JSX 中直接执行 `createMemoryApiClient(...)`，每次 render 创建新对象。
3. `MemorySettingsPanel` 的 `refresh` 依赖 `api`，加载 effect 又依赖 `refresh`。
4. 父级 render → api 引用改变 → refresh 改变 → effect 重新请求 status/assets → loading true/false。
5. 重复请求还会把翻页位置重置到第一页。上一轮的 loading 文案和按钮禁用状态让重复请求表现为可见闪烁。

修复：父组件按稳定的 HTTP client 创建 `useMemo` API 实例；记忆面板只在进入、用户刷新、查询条件改变、单条操作成功、记忆配置实际激活后请求。父级配置状态轮询不触发记忆列表请求。

保持请求序号或 AbortController，过时响应不得覆盖新的筛选和页面；组件卸载后不更新状态。单条操作使用 memoryId 级 busy，不能让整个列表反复禁用。一次请求期间禁止重复提交相同操作。

首次进入才显示固定高度的骨架。后续刷新保持已显示的列表、滚动位置、详情和按钮尺寸，只在刷新按钮旁显示细小状态。刷新失败保留当前内容并显示「刷新失败，当前内容可能不是最新」，不得变成空列表。

这里保留的是当前组件已渲染的内容，不新增本地持久缓存，不写 localStorage，不复用旧接口响应代替新请求。

## 3. 页面信息结构

从上到下：

1. **页头**：「记忆」与说明「管理 MetaWork 记住的偏好、背景和事件」。右侧显示实际运行状态和「记忆设置」。
2. **作用域说明**：「这些记忆仅用于当前账号，可在不同工作区的相关任务中使用。」
3. **工具栏**：全文关键词搜索、类型筛选、全部/可使用/已停用筛选、刷新。
4. **结果摘要**：「共 3 条」；筛选后显示「找到 1 条，共 3 条」。数量来自服务端真实结果。
5. **紧凑列表**：内容摘要最多两行，中文类型、小型状态文字。整条内容区域可点击打开详情；不在每行并排堆放停用与删除大按钮。
6. **分页**：超过 50 条才显示；翻页保留搜索和筛选。删除末页最后一条回到上一页，既有修复保留。
7. **右侧详情**：完整正文和管理操作。窄屏变为全屏详情，通过「返回记忆」回到原滚动位置。

类型映射：instruction →「偏好与要求」；persona →「个人背景」；episodic →「事件记录」；其他类型使用产品字典，没有对应项时显示「其他」。不根据正文关键词擅自修改类型。

列表摘要是正文的截断展示，不新增 LLM 摘要请求；详情必须请求完整正文，不能把现有最多 240 字的 preview 当作全文。

默认顺序按更新时间降序，再按稳定 ID 排序。搜索在全部记忆的完整正文中执行，筛选在分页之前执行，不能只搜索当前 50 条。暂不自动跳动排序；用户刷新后统一更新。

## 4. 详情与用户操作

详情标题为「记忆详情」，正文可选择和复制。依次展示中文类型、可使用/已停用、完整正文、更新时间、来源。没有可靠来源信息时显示「来源未记录」，不得捏造对话链接。已有字段没有来源会话标题，补齐契约后才启用「查看来源对话」。

### 查看

点击列表行 → 详情加载 → 显示全文。高亮只对应一个 memoryId。浏览其他条目不修改记忆。详情加载失败保留列表，并在详情内重试。Escape 关闭，焦点回到触发行。

### 停用与恢复

详情中提供「允许在相关任务中使用」开关，旁边说明「关闭后保留这条记忆，后续不会作为新的记忆证据提供给任务」。点击即提交，不弹确认。仅该项显示处理中，收到成功响应再更新状态；失败显示原状态和就地错误。成功提供「已停用 / 已恢复」的轻量提示。

停用不会撤回已经发送给运行中任务的内容，也不修改历史任务。全局关闭和单条停用是不同动作：全局开关停止后续记忆服务；单条开关只管理这一条。恢复全局功能不得重新启用此前单独停用的条目。

### 删除

放在详情底部的次要危险操作，不在列表里占据主要视觉位置。点击只进行一次确认，展示待删内容摘要。

文案：「删除这条记忆？删除后无法恢复，不影响原始对话和已生成的文件。」按钮为「取消」「删除记忆」。后端成功后移除该行、关闭对应详情、更新总数；失败保留内容并给出可重试错误。

当前能力没有可靠的删除撤销，因此不提供虚假的「撤销」。删除当前资产也不等于永久禁止系统从新的对话中重新记住相同内容，页面不得承诺永久遗忘。若产品要支持永久忽略，应作为独立领域能力设计。

### 内容有误时如何纠正

目标体验：详情点「编辑内容」→ 原位多行编辑 →「保存修改 / 取消」。不让用户去另一个对话里重新描述；不把多个格式偏好前端擅自拆成多条。编辑时保留未保存文本，关闭详情时只在确有未保存变更的情况下确认。

**这是后续能力，不冒充现有接口。** 当前 MetaWork 管理 API 只有列表、停用、删除，且 ADR-0049 限定写入 L0。虽然引擎有 atomic update 接口，也不能让前端直接调用。实施编辑前需修订该 ADR 的治理例外，扩展 MemoryService/Port 的账号内编辑能力、校验与净化、expectedVersion 并发控制、召回候选失效和索引更新，防止旧正文在后续任务被继续使用。发生版本冲突时保留用户文本，让用户选择重新加载对照，不静默覆盖。

首版详情先交付全文、停用、恢复、删除；编辑原型标注为后续设计，正式页面不展示不可用按钮。

## 5. 记忆设置

从主列表分离，点击「记忆设置」展开同页面的次要区域，不另造设置页面。

折叠时仅显示实际状态（已开启/已关闭/需要设置/暂不可用）。展开后显示全局开关、当前抽取 Provider 与简短 Model ID、费用说明，以及必要的保存操作。

模型介绍放在辅助信息，不再把整段英文描述作为 select 的选项名称。默认只展示可用 Provider；不可用项及原因放到「查看不支持的模型服务」折叠内容，并翻译为用户能理解的原因。

全局配置继续遵守现有「保存并激活」事务。编辑开关不应伪装已生效：明确显示「待保存」，只有激活成功才更新页头实际运行状态。单条停用与删除立即生效，不依赖整页保存。

不把引擎健康等同于某条记忆已使用。后续若展示「最近使用」，必须来自真实的记忆引用/证据访问记录，且区分被召回、被引用、被 Executor 读取；没有记录不编造次数和时间。

## 6. 空、错、慢与窄屏

| 场景 | 用户看到什么 | 操作 |
| --- | --- | --- |
| 首次加载 | 固定高度骨架与一次「正在读取记忆」 | 无反复动画刷新 |
| 没有记忆 | 「还没有保存的记忆。相关对话会在后台整理为记忆。」 | 可查看记忆说明 |
| 筛选无结果 | 「没有找到相关记忆」 | 清除筛选 |
| 刷新中 | 原列表保持，刷新按钮显示处理中 | 不跳顶、不重置分页 |
| 读取失败 | 错误位于列表顶部；已有内容保留并标注非最新 | 重试 |
| 引擎不可用 | 「记忆暂不可用」和可操作原因 | 打开设置/重试；不伪装零条 |
| 全局关闭 | 明确「记忆已关闭」 | 引擎未运行时不请求资产；不把不可读取当作零条 |
| 单条操作中 | 仅对应条目及操作忙碌 | 其他记录仍可浏览 |
| 390px 宽 | 工具栏换行；详情全屏；动作固定在底部 | 无水平滚动 |

键盘：行使用真实 button；Enter 打开，Escape 关闭；详情和确认框管理焦点；图标按钮有中文 accessible name。使用中/停用同时有文字，不只依靠颜色。按钮点击区域至少 40px；主操作 44px。适配现有深浅主题和 reduced-motion。

## 7. 必要接口与边界

首版实现范围：消除重复请求、列表重排与中文类型、全文详情、账号内全文搜索/状态及类型筛选、分页、单条停用/删除、配置区域折叠。

- 保留现有 status、assets 列表、assets/enabled、DELETE 接口。
- 扩展列表参数 q/type/enabled/order；所有过滤先于分页，total 为过滤后的真实总数；账号归属保持 Server 注入。
- 增加账号内资产详情查询，返回全文和真实时间/来源；已停用条目也能由用户查看。不能借用只允许 enabled 记忆的执行 evidence 物化接口来实现用户管理。
- 数据流固定为 Web → Management query → MemoryService → Memory Port → 引擎。前端不读数据库、不持有引擎凭据。
- 编辑内容及使用记录是独立后续范围；更新 ADR、CONTEXT 和当前技术说明后再实施，不趁 UI 改造绕开治理契约。

## 8. 验收标准

1. 设置页持续打开 30 秒，父级每秒轮询依然运行，记忆列表/状态请求不随它重复，刷新按钮不闪烁。
2. 至少 120 条记录；第 3 页停留 10 秒不跳回首页；全文搜索命中不在当前页的条目。
3. 500ms–3s 网络延迟下快速修改筛选，旧请求不能覆盖新请求。
4. 详情超过 240 字仍能完整查看与复制，中文类型没有英文枚举泄漏。
5. 停用成功后展示真实状态，失败时不伪装成功；重新进入保持结果。
6. 删除先确认、失败不丢行；删除末页最后一条自动返回合法页。
7. 刷新保持视口与已打开详情；失败时提示内容可能非最新。
8. 无数据、筛选无结果、引擎不可用、全局关闭四种状态可区分。
9. 390px、1440px、深色主题、键盘操作分别实测；焦点与滚动不丢失。
10. 若实施编辑，再单独验证并发冲突、索引更新、召回失效、用户修改不被后续自动合并悄悄覆盖。
