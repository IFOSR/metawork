## 目标与边界

决策模型比较任务与验收要求、用户职责、模型的具体优势、局限、适用任务和人民币价格；不再通过泛化标签数量或关键词重合猜测谁做得更好。公开资料是能力证据，不等于实测质量。缺失资料不解释为没有能力，也不解释为免费。

保留图片输入/产出、结构化输出、工具协议、上下文、Provider/Harness、权限、健康、已授权模型池及显式预算检查。受控交付契约（例如图片产物）不是质量标签，保持现有 Planner/Kernel 校验。固定选择不改为自动选择。

## 所有权与实现

1. Routing 拥有统一候选过滤、决策问题和确定性排序：移除标签计数优先级、自然语言关键词打分；有效决策概率优先，失败时使用已有显式成本/延迟/质量策略和稳定顺序。
2. Configuration 提供 revision 固定的职责、工具条件与模型事实。决策模型直接读这些自然语言证据，并推导该候选 Agent 的可执行能力；不把 UI 临时生成的改写缓存当运行时权威，不新增第二份易过期的能力存储。
3. Application Shell 继续负责唯一决策模型调用。Kernel 只读取并验证有版本的 observation，检查事件、配置、候选身份；不调用 LLM，不改变重放和已执行决定。更新 question/policy 版本以拒绝旧问题结果。
4. Web 用“能力与适用范围”展示 summary、strengths、limitations、preferredTaskTypes、avoidTaskTypes 的自然语言内容；保留公开参数卡片，去除“不参与路由”的错误说明和泛化标签列表。
5. Planner 图像输入转为明确的 vision 硬条件；原来以偏好标签模拟输入约束的分支删除。没有新增语义路由、Storage schema 或权限授予路径。

依赖保持 Shell → Routing/Configuration、Kernel → 纯 Routing 值与规则、Web → Management API。无临时例外。

## 验证

路由测试覆盖标签差异不能胜过决策概率、同标签不同文本提供给决策模型、无决策时不做关键词猜测、技术与权限过滤仍有效、固定选择、旧问题版本拒绝与回放。检查实际人民币价格及未知价格语义。运行 owning seam 测试、类型检查、构建和设置页浏览器验证；验证通过后更新已安装服务。
