## 交付行为

新安装预设三个角色：总管、助理、分析师，均提供职责说明。保留原有 `planner`、`pi-engineering`、`pi-research` 内部标识与受控执行权限；角色名称不构成新的语义路由或权限授予。已有账号的自定义名称、职责、额外角色和模型绑定不会被默认模板覆盖或重复创建。

设置中的总管始终启用，不再提供停用开关。首次未配置模型时，三个预设在设置草稿中默认启用并标注“待绑定模型”；用户必须为每个启用角色选择自己的模型，才能保存并激活。无凭据安装快照仍按现有契约保持不可执行，不能以默认启用 UI 绕过模型、凭据和配置激活校验。安装时已显式提供用户模型的场景，三个角色直接沿用该明确输入并启用。

仅识别三个名称、职责、未绑定策略均符合产品模板、且全部未运行启用的首次安装快照，才自动暂存默认启用状态。用户之后主动停用的角色不会被模板重新启用，也不会补回已删除的角色。总管作为必需入口，在设置中重新绑定和保存前仍受现有工作就绪检查约束。

未绑定的角色提供“绑定模型”入口，展开对应编辑器；无模型时提示先添加 Provider/模型，有模型时提示明确选择。保存按钮旁按角色名称列出未完成项，区分“默认启用、待绑定”与“可执行”，不再让用户面对无解释的禁用按钮或“没有可用模型”的误导提示。
