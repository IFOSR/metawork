- 本文取代此前同路径文档中的 detached worktree 副本方案。
- 后续架构参考：[两级 Worktree 评估](2026-11-02-subtask-worktree-feasibility-assessment.md)。
- 较早备选：[共享目录只读并行初稿](2026-11-02-read-only-dag-parallelism-proposal.md)。其整图只读资格不再作为当前建议。

## 审阅摘要

每个 Subtask 声明对会话业务目录的读写效果。启动时原子申请资源租约：读读
兼容，读写互斥，写写互斥。只读节点共同读取现有会话目录，临时文件写入独立
scratch；写入节点继续原来的会话目录执行、Git 封存与 Task 交付。

整个 Task 可以包含只读与写入节点。先并行调研再生成报告、先修改文件再并行
分析都支持。依赖和容量仍由现有调度链路判断，不增加按拓扑层同步的阶段屏障。

不建立任何新 Worktree、输入文件副本、Subtask 分支或合并队列。代价是同一个
会话业务目录的写者必须等待所有读者释放，读者也不能与写者同时访问实时文件。

在现有可信原生 Executor 边界内，完整实施与专项验证粗估 4–7 人日。它比上一版
6–10 人日少了副本/版本绑定流程，但节点契约、会话占用和恢复仍必须改动。若要求
OS 强制禁止 Executor 写业务目录，需另评估 Host 沙箱，不能计入该估算或宣称
资源锁已经提供此保证。

## 1. 节点声明与首期范围

新增节点级结构化 Workspace effect，建议取值语义为只读、写入、无法确定；
最终字段名与 schema 版本在实施设计中固定。Planner 声明，图验证检查一致性，
随 Subtask 与 graph revision 持久化，Runtime 按授权事实申请锁。

- 只读指不修改会话业务文件，不禁止自己的临时区写入。
- 写入包括编辑、新建、删除业务文件；即使无下载附件也属于写入。
- 无法确定/缺失的旧事实继续按独占处理，不靠标题或模型名字猜测。
- `report` 和 `fileOutputs=[]` 不能单独证明只读。
- Task 总体可以写入，不能据此把所有子节点都变为写入；Task 总体只读与子节点
  明确写入的矛盾则应返回提案反馈。
- 外部动作、服务启动、数据库和端口访问继续遵守原资源契约，Workspace 只读
  不代表外部资源没有副作用。

首期开放显式只读、文本结果/文本交接节点的并行。需要文件交付的节点仍采用
现有独占完成路径；这只是本期交付接线边界，不是把 fileOutputs 当作写入判据。
串行的报告生成/代码修改节点可声明自己的文件输出，不限制整张图。

节点 effect 只用于资源/效果契约，不删减 Harness 工具表，不增加 per-tool
Kernel 审批，也不让 Runtime 接管 Executor 的内部工具循环。

## 2. 每次启动的判断

1. 现有 DAG frontier 确认前置节点及 handoff 完整，图版本/取消 fence 有效。
2. 确认账户与 Task 并发名额、Executor 可用。
3. 申请会话业务根资源：符合首期资格的节点申请 read，其他节点沿用 write；
   节点自己的 scratch 申请独立 write 资源。
4. 在同一事务中检查资源冲突并取得租约。冲突记录等待，释放后通过现有事件
   路径重新检查；不得先查询“没有写者”再异步启动。
5. 获得必要占用后才启动 Executor，并持续心跳。启动中、取消清理中的占用
   同样参与判断，不能只看 UI running 状态。

| 同一会话业务目录的有效占用 | 新读者 | 新写者 |
| --- | --- | --- |
| 空闲 | 可启动 | 可启动 |
| 一个或多个读者 | 额度允许即可启动 | 等待 |
| 一个写者 | 等待 | 等待 |

沿用 `resourceClaimsConflict()` 的既有规则和 Repository 的 immediate claim
事务；本期不引入路径级细粒度调度，写者仍锁整个会话业务根。无冲突的其他会话
按现有账户容量继续运行。等待写者不能被无限新增的读者饿死，复用等待事实定义
稳定准入顺序；不让尚未运行的整层节点阻止已满足依赖的工作。

## 3. 目录与临时文件

所有节点仍以现有 Conversation Worktree 为业务输入来源。只读节点的进程 cwd
建议放在账户 Runtime 下的 attempt 专属 scratch，输入上下文显式给出会话
业务根和必要材料的绝对路径，使默认相对路径写入留在自己的临时区。

scratch 放在会话目录外，不位于其父路径 write/read 租约之内，避免新增临时
文件与业务根读锁冲突。每个节点独立设置 TMPDIR/工具缓存路径及 Runtime 可控制
的下载/中间产物位置；证据与 handoff materializer 写入自己的 attempt 目录。
已有工具不可配置的共享缓存仍需专项核对，不能仅设置 TMPDIR 就假设全部隔离。

写入节点的业务 cwd 继续是 Conversation Worktree。两种执行上下文都使用原
Workspace 身份和绑定，新增受管 scratch 事实，不暴露新用户 Workspace 或可选
执行模式。路径校验要明确区分业务根与临时 cwd，不能误用旧 in_place 回退分支。

输入读取期间由 read lease 阻止受管业务写入。记录观察到的会话 head 便于审计，
不承诺任意历史版本重放：若重试时 head 已因合法写入变化，旧执行上下文不能
静默沿用；应按现有恢复校验报告输入变化并重新协调。普通同批读者期间 head
应保持稳定。业务目录可包含此前已封存的其他分支成果，沿用共享会话文件视图，
结果交接仍必须走声明的 DAG 边。

## 4. 会话占用只保留一套职责

现有 `claimConversation()` 使用单一 Attempt owner_token，会继续把所有读者
串行化，必须连同调用方迁移：

- Task/Conversation slot 管理“一会话一个顶层 Task”和生命周期。
- 每个 Attempt 的 read/write 租约管理业务文件并发。
- Planner 观察、会话同步、清理及 Git 封存遵守同一占用事实；任何修改业务树或
  受管 head 的操作都须等待读者结束并取得对应独占资格。
- 已有 Git 公共元数据短锁继续使用，不持有全仓长锁运行模型。

不另造一套进程内 activeReaders 作为权威。多读者归属由持久化租约/Attempt
事实表达，一个读者退出只释放自己的占用，不能将整个会话提前置 idle。

现有资源查询按 TTL 筛选租约，迁移 owner 后必须核对旧进程 fencing：租约
过期不能证明进程死亡。未确认停止的残余进程仍阻止冲突操作，保持 recovery
等待；以 owning seam 测试证明取消和崩溃后不会出现第二个冲突执行者。

## 5. 完成、封存和读写转换

只读节点：收束相关子进程，核验会话业务文件未被修改，保存 receipt 和文本
结果，同事务写 done 与 outgoing handoff，然后释放该节点资源。每个节点
独立完成，不必等所有读者才保存文本结果；最后一个读者退出后，写者才可进入。
只读完成不调用会话 sealAttempt、不推进分支、不创建文件交付。

写入节点：继续原封存和完成路径，write lease 覆盖执行、残余进程收束、封存
及必要落库。在释放前必须完成对后续读者可见的版本更新，避免读到半写入状态。
Task 最终按真实变更交付文件；包含只读节点不会使整个 Task 跳过交付。

执行中发现需要业务写入时，不允许持有 read lease 就直接写，也不在持有读锁
时阻塞升级为 write（多个读者同时升级可能死锁）。通过既有反馈/修订和恢复
路径形成后续独占执行，保留已产生的可用文本结果；具体再执行由协调链路管理，
不在 Runner 内增加重试循环。

response-only correction、部分结果接受、重启补落与 finally 清理必须使用
同一持久化节点事实，不能因存在 Conversation binding 就封存只读任务。

## 6. 原生执行的实际边界

ResourceLease 协调参与协议的执行者，不是 OS 文件权限。当前原生 Executor
可使用 shell，单靠 effect、cwd 和提示不能保证它不会按绝对路径写入会话目录。
本期在已有可信 Harness 模型下实施，只读说明与临时目录约束属于执行契约，
结束时的业务树校验属于异常检测，不宣称实现了强隔离。

如果检测到业务树意外变化：记录共享输入污染，暂停新的相关 dispatch，收束
相关活动读者，保留现场并进入一致性恢复，不自动封存为某个只读节点的合法成果，
也不回滚覆盖其他未知修改。已生成结果需检查有效性，不能因为文本存在就认证为
基于稳定输入。执行后检测无法撤销读者此前看到的内容，验收/发布说明必须体现
这一限制。若产品要求彻底消除此风险，需先增加 Host 文件保护或使用隔离副本；
不能靠修改锁规则达到该保证。

## 7. 界面和运行范围

节点展示运行中、等待并发名额、等待写入完成、等待其他节点读取结束、等待
前置结果等状态，来自统一服务端投影。依赖独立数与实际运行数分开呈现。

当前任务配置为账户 4、单 Task 2。实施后默认两个只读节点运行、第三个等名额；
若需要三个同时运行，单 Task 额度和账户空闲额度都须至少为 3。

新图采用节点 effect 契约，运行 generation 不热切换，不为验证而重跑已完成
成果。历史缺少节点字段的未完成图保持既有独占事实；迁移/恢复规则需在 ADR 中
明确，不能把历史缺失字段补猜成 read。

## 9. 验收标准

- 三个只读节点执行时间真实重叠；额度 2 时只启动两个，释放后第三个启动。
- 同一图先并行只读，再独占写报告；也能先写入封存，再并行读取新内容。
- 原子启动：读读成功，读写/写写互斥；节点结束只释放自己的租约。
- 写者封存/进程清理前不释放；TTL 过期和重启不使存活的冲突执行者被绕过。
- scratch 同名文件互不影响，不进入业务 delta、Git、附件或最终交付。
- 只读结果及 handoff 同事务完成，下游不会提前启动；Task 文件交付正常。
- 意外业务写入不被封存为合法只读成果，相关输入污染可观察且阻止新 dispatch。
- 取消、崩溃、重试、部分结果接受、补落和清理不重复启动、不误封存共享目录。
- 普通 Harness 工具保持可用；无法确定效果、文件交付与外部资源不被误判可并行。
- 完成 owning-seam 测试、数据库/Docker 回归、lint 与原生混合图 smoke。
