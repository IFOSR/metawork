# Planner Search Ownership Handoff Implementation Plan

> **For Codex:** Implement this plan task-by-task with test-first changes and
> preserve the Planner -> Kernel -> Runtime -> Executor ownership chain.

**Goal:** Remove public-Web reconnaissance from the MetaWork Planner, route
research requests directly to an authorized research Executor, and make
Planner convergence exhaustion a typed, fail-closed terminal outcome.

**Architecture:** The Planner remains the only natural-language semantic
owner, but no longer receives `web_search` or `web_fetch` in MetaWork-managed
Planner sessions. It uses the authoritative MCP context and the live v8
proposal schema to submit a `current-web-research` Work Graph; the Executor
performs final search/fetch work using the user's materialized input. Planner
convergence exhaustion is not a transport uncertainty and never synthesizes a
fallback plan: it preserves bounded audit/trace facts, creates no Task or
Kernel event, and asks the user to retry or narrow the request.

**Tech Stack:** Node 22.19+, strict TypeScript ESM, vendored AnyFusion-Pi,
Vitest, Zod, SQLite-backed Planner proposal persistence, Gateway interaction
trace.

## 1. Design Decisions

### 1.1 Search ownership

- MetaWork-managed Planner sessions expose no `web_search` or `web_fetch`.
- Research, current public information, supplied URLs, reports and citations
  remain Executor-owned work.
- Planner must still read `get_planning_context` and the revision-pinned
  Executor manual/catalog before submitting a research graph.
- A research subtask uses `current-web-research` and
  `{ "kind": "current_user_input" }`; Work Graph materialization persists the
  complete bounded user input, including any URL, for the Executor.
- Executor search/fetch implementation remains the business execution path.
  Its egress/SSRF boundary must be verified as part of focused tests; Planner
  removal must not silently widen access to private network targets.

### 1.2 Convergence exhaustion

- Processing-cycle and non-proposal-tool budgets remain 8 and 12.
- Exhaustion is a distinct `convergence_exhausted` failure with a stable reason
  for `processing_cycles` or `non_proposal_tool_calls`.
- `transport_uncertain` remains reserved for an uncertain proposal/Kernel
  handoff that can replay the identical submission.
- A convergence failure does not contain a proposal identity and is never
  replayed as a proposal.
- No fallback Plan is generated by Session. No Task, Kernel event, or Executor
  attempt is created.
- The current turn ends with a safe, actionable message: Planner did not
  complete within its bounded planning budget; no Task was created; retry or
  narrow the request.
- A later user message is a new semantic turn. It is not an automatic outer
  repair loop and does not replay a nonexistent proposal.

## 3. Rollback Boundary

The change is isolated to Planner capability exposure, Planner failure typing,
Session presentation, tests and documentation. It does not change Work Graph
v7, PlanningAgentPlan v8, Routing Capability definitions, Kernel policy,
Executor search logic, or persistence schema. If Planner prompt behavior
regresses, disable the new Planner artifact/release while retaining the
MetaWork-side typed convergence handling; do not restore a second semantic
router or automatic research fallback.
