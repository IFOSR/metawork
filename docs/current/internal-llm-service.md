# MetaWork 内部 LLM 服务

内部 LLM 是 MetaWork 的系统功能，由研发维护。当前服务于智能体职责的“AI 改写”、智能体的“能力更新”和模型编辑的“获取模型信息”。它不依赖 Planner，也不使用用户账户的模型选择、路由决策模型或 Provider 配置作为内部服务连接。

## 独立配置

安装根默认为 `~/.metawork`，可由 `METAWORK_INSTALL_ROOT` 指定：

- `internal/llm.json`：连接与生成配置，参考 [配置样例](../../examples/internal-llm/llm.json)。
- `internal/llm-credentials.json`：独立凭证文件，权限 `0600`，采用既有 SecretStore 文档格式：`version: 1`、`providers: {}`、`internal: { llm: "实际密钥" }`。

`llm.json` 不保存明文 Key。`apiKeyRef` 只允许内部命名空间，默认 `file-secret:anyfusion/internal/llm`，对应独立凭证文件的 `internal.llm`。两个文件均不属于账户 revision，不返回给 Web，不会被删除 Provider 或切换 Planner 模型覆盖，也不进入源码仓库。

| 字段 | 要求 |
| --- | --- |
| `provider` / `displayName` | 研发维护的标识和名称，不参与用户 Provider 查找 |
| `baseUrl` | OpenAI 兼容 API 根地址，程序追加 `/chat/completions`；不可包含用户名、密码或查询参数 |
| `modelId` | Provider 实际接受的请求 ID；当前平移已有配置的 `deepseek-flash` |
| `apiKeyRef` | 独立凭证文件中的内部引用 |
| `enabled` | 是否启用 |
| `timeoutMs` | 500–120000 毫秒；当前安装为 60000 |
| `maxTokens` | 512–16384；当前安装为 4096 |
| `thinking` | 可选 `enabled` / `disabled`，供支持此参数的 Provider 使用；切换到不支持该参数的服务时删除 |

每次调用重新读取配置和凭证；研发更新文件后，下一次请求生效。建议通过临时文件与原子重命名替换，避免读到半写入配置。正在运行的请求使用启动该请求时的配置。无效配置明确报错，不静默改用其他 Provider。当前传输协议为 OpenAI 兼容 Chat Completions；原生 Anthropic 协议需要先增加传输支持。

## 一次性从用户 Provider 复制

用户明确授权后可运行：

```sh
node scripts/configure-internal-llm.mjs --model-ref default-model
```

可加 `--install-root`。脚本从 local-default 的 active revision 找到该模型与 Provider，将 Base URL、实际模型 ID 及 Key 复制到上述独立文件。它不会改变账户配置或凭证，不会打印 Key；若内部配置已存在则拒绝覆盖。此操作不会在启动时自动执行，之后两套配置独立维护。

## 功能边界与失败反馈

AI 改写以用户职责为主，模型事实为背景，生成中文核心职责、具体任务、交付物、质量要求和边界。程序只校验和排版；失败时保留原文，不用模板冒充 AI 输出。

“获取模型信息”先免登录获取 OpenRouter 目录、按模型 ID 匹配或由用户确认候选，再调用内部 LLM 提炼 `routingNotes`：摘要、优势、局限、适配任务和不适配任务。仅对选中模型调用 LLM，不对整个目录逐项生成。API 只接受 catalog model ID，原始资料由服务端读取。LLM 提炼失败时保留旧路由标签，并明确区分“公开资料已获取”和“标签未更新”。

生成的任务标签与详细画像保存到同一个模型配置中的 `routingNotes`，通过现有配置激活进入 Planner/Kernel 投影和路由决策输入。OpenRouter 描述与结构化资料保留展示；模型硬能力、工具权限和价格不由 LLM 任意改写。目录信息是公开声明，不是实测质量保证。

智能体的“能力更新”根据已选模型的公开资料与可用工具，单独生成以智能体为主体的中文总述、具体工作能力和使用边界，不展示模型厂商、架构或英文介绍。展开智能体时自动整理；更换模型或资料变化后重新生成，手动更新可跳过缓存。相同资料复用最多 64 项进程内缓存，失败不缓存。该说明仅用于用户理解，不新增能力权限，不替代职责或修改路由配置；多候选的差异能力需要明确适用条件。模型公开资料的抓取仍在模型编辑中完成。

“AI 改写”与“能力更新”在对应内容旁展示处理中、已更新、内容无变化或失败，显示等待秒数及完成时间，支持查看本次更新前的内容。无变化仅表示返回内容与原文一致（忽略空白差异），不把失败解释成“质量已经足够好”。职责改写成功只填入编辑草稿，保存并激活后生效；请求期间继续编辑职责或切换模型时，迟到的建议不覆盖新输入。浏览器对这些调用设置 150 秒兜底超时，失败时保留当前内容并可重试。

## 保存与 AI 操作的边界（2026-10-05）

“AI 改写”“能力更新”与模型公开信息整理使用本服务；用户的 Planner 模型只负责
面向用户的意图理解与任务编排。保存并激活不调用任何 LLM，只执行校验、编译、
持久化和热切换。旧的 Planner 配置说明书解析链路已移除；内部 LLM 不可用时，
AI 操作会明确失败，仍可手动编辑并保存职责。
