# Git 文件策略后续技术债

- **记录日期**：2026-07-27
- **状态**：待后续版本处理
- **历史实现计划**：[Phase 6 上](../archive/plans/2026-07-27-phase-6a-single-task-concurrency-and-git-integration.md)

Phase 6 上把所有新文件任务统一到 MetaClaw 托管 Git，并只实现文本三方合并与不可合并二进制独占发布。下列能力有意不在当前版本实现：

1. SQLite 等数据库的语义快照、记录级比较或应用级合并。当前被 Git 追踪的数据库文件按不可合并二进制处理，只适合静态快照和测试 fixture。
2. 活跃数据库、WAL/journal、日志、缓存和数据库数据目录的专用生命周期。这些路径不应进入 Git 合并通道，未来由对应服务或资源租约管理。
3. Git LFS 存储大型二进制。LFS 只解决对象存储与传输，不改变同一路径二进制不可语义合并的规则。

后续实现必须复用 ADR-0025 的 publication、文件级 lease 和“冲突不静默选边”契约，不得引入第二套工作区版本账本。
